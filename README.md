# OPTIMUS HeatRoute — комплект передачи

Сложная территория — оптимальное подключение.

Сервис автоматически строит варианты новой тепловой сети, рассчитывает расходы, диаметры и стоимость, показывает результат на карте и выгружает GeoJSON.

## Результат

**17/17 подключений. Строительство 431 306 579,53 ₽. Новая сеть 3 520,886 м. Штраф 0 ₽. S = 22,639241120.**

Стоимость уменьшена относительно предыдущей полностью подключённой схемы на 4 731 165,79 ₽, длина — на 54,712 м. Глобальный минимум не доказан.

## С чего начать

1. `START-HERE.md` — запуск на Ubuntu Server 22.04 и docker-compose 1.29.2.
2. `results/result.geojson` — все три варианта; `results/best-variant.geojson` — лучший; `results/result.report.json` — протокол.
3. `visualization/result.html` — интерактивная карта, открывается без сервера.
4. `presentation/` — презентация на 8 слайдах, PDF и сведения для конкурсной подачи.
5. `docs/COMPLIANCE.md` и `docs/VALIDATION.md` — статус требований и проверок.

## Состав

`backend/` — исходники, интерфейс и тесты. `release/optimus-heatroute.jar` — готовый сервис. `Dockerfile` собирает исходники и выполняет тесты. `docker-compose.yml` запускает приложение и PostgreSQL/PostGIS. Отдельная конфигурация `compose.prebuilt.yml` запускает готовый JAR.

`data/corrected.geojson` — фактически рассчитанный вход. `data/input-provenance.json` — отличие от ранее переданного файла. `references/` — неизменённые документы организатора и прежний набор. `evidence/` — протоколы проверок. `full-project.txt` — текстовые исходники проекта. `SHA256SUMS` — контрольные суммы поставки.

## Границы подтверждения

Основной режим — cost: выбирается допустимое место прямого ввода в собственный ОКС с учётом стоимости. Результат 17/17 относится к нему. В позднем приложении §2.2 и разъяснении №3 есть формулировка «от ближайшей к точке границы полигона». Режим cost не проверяет глобальный геометрический минимум до границы; формальное соответствие этому пункту не подтверждено. Сохранён отдельный режим nearest.

Целевой стек: Ubuntu 22.04, Java 11, Spring Boot 2.6.3, PostgreSQL/PostGIS и docker-compose 1.29.2. Наличие конфигурации не означает пройденную инфраструктурную приёмку: фактический запуск Ubuntu/Docker/PostGIS в среде подготовки не выполнен. Остальные проверки перечислены в docs/VALIDATION.md.
